Problem
Seven guards each carry a private, ad-hoc parse of Nextflow source, and each has a different blind spot — so a guard's interface ("it passed") says nothing about whether it read the file.

The closure that throws
errorStrategy = {
    if (task.attempt <= 3) return 'retry'
    log.warn "SEG_QUALITY_EVAL dropped ..."
    return 'ignore'
}

log is not bound in conf/*.config closures. It resolves against ConfigObject — the exact silent-resolution trap CLAUDE.md documents for lib/ classes, but with log, so it was never recognised as an instance of it. Past the retry budget Nextflow reports an unknown method invocation on ConfigObject and exits 1. The 'ignore' branch is unreachable: the block does the opposite of what its comment promises.

The default-on selector that hides failure
errorStrategy = { task.exitStatus in ((130..145) + 104)
    && task.attempt <= 3 ? 'retry' : 'ignore' }

An exit 1 — an ordinary Python traceback — is dropped on attempt 1. The selector covers WARP_SEG_QC, and reg_qc=2 is the default. A broken warp_seg_qc.py therefore yields a green run with no *_seg_qc.json, no residual CSVs, and a SpatialData .zarr missing its obsm blocks.

Constraint that shapes the seam: conf/*.config cannot see lib/*.groovy, and under Nextflow 26's strict parser there is no legal way to share a helper between two withName: blocks — top-level def fails to parse, top-level closure assignment is rejected as a dynamic option. So the deepening cannot be "extract a policy class". It has to be: reduce the number of distinct policies to a small named set, inline each verbatim, and assert on the config text through Candidate 1's model. That is the only seam the platform permits.
Problem
Failure policy is scattered literal closures in a file no test can execute, in a scope where the obvious refactor is illegal. Two of them are wrong, and both hide it.
Solution
Three named policies — retry-then-fail, retry-then-drop, fail-fast — inlined at each site, plus a guard asserting no errorStrategy closure calls an unbound identifier.
Wins
  • Aborting closure caught statically
  • "Ignore" becomes a stated choice
  • Green run implies complete tree

Top recommendation

Tackle first

Candidate 1 — one Nextflow source model behind the guard layer

Not because it is the most severe defect — retry.py is — but because it is the one that determines whether you can trust anything else you fix. This audit found four guards that pass while checking nothing, and the pattern is always the same shape: a private regex parse with a blind spot nobody can see from the interface. Until the parse is one deep module with its own meta-test, every future green run is an open question, and CLAUDE.md's standing warning — "watch every new guard fail before you trust it" — stays a manual ritual rather than a property of the code.

It is also the cheapest. The correct parser already exists at tests/test_layout.py:347, complete with a meta-test guarding its own blind spot. The first move is an import, not a design.

Sequence after that: fix retry.py and export_geojson.py:342 (two small edits, both on the critical path) → fast-forward main → add benchmarking to ci.yml's triggers (one line, collapses two findings) → then Candidate 2, which closes four defects at one seam.
