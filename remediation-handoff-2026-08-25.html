Four things that will bite you

Shipped breaking change

Checkpoint CSVs now carry an id column (Ruling R17). An existing --prior_outdir for add_cycle, or --start X against a pre-change outdir, fails loudly with an actionable message instead of silently misreading. This is intended, but it is user-visible and must appear in the Phase 9 migration note alongside the darkfield and NaN-measurement changes.

The plan is not a spec

Every task in Phases 0–4 found at least one brief premise that dev's history had already overtaken — including a nextflow.config property that does not exist on the pinned plugin and would have aborted every launch, a query function that could never have matched anything, and two controller rulings that were simply wrong. Tell every implementer the brief may be stale, and that reporting a stale premise counts as success. That single instruction produced most of the findings below.

Before touching config

Grep tests/ for an existing guard on the surface you are about to change. dev added ~40 test files encoding rules invisible from the code they protect. Two of them constrained the --concurrency design after the fact (R9, R10) — one forbidding an elvis form that had been written in seven places.

Verify the mechanism, not the outcome

Four assertions in this repo were found whose stated subject and real subject diverged, all passing. The only reliable detector is to plant the violation the guard claims to catch and watch it fail. Where a fix makes two things agree, the test must exercise both derivations end to end — a test that supplies either side tests the assumption, not the code.

Two errorStrategy closures call log.warn. log is not bound in conf/*.config — it resolves against ConfigObject, throws past the retry budget, and aborts the run. Ruling R3 — ordering

Run Task 6.4 immediately after 5.3, before the rest of Phase 6. 5.3 makes a failed QC task fatal; 6.4 fixes the silently-ignored optional: true that 5.3 unmasks. Any gap between them leaves the default path failing.

The seam is constrained: conf/*.config cannot see lib/, and NF26 forbids sharing a helper between withName: blocks. So the fix is reduce to three named policies, inline each verbatim, and assert on the config text through tests/nfmodel.

Why this sits after Phase 5

nextflow.config's own comment gives two reasons cleanup_work shipped false. One — that it destroys evidence for tasks dropped by the errorStrategy 'ignore' branch — is eliminated by Task 5.3. Doing 6B first would delete the evidence for silently-dropped tasks.

--cleanup_level=none must survive as the level you pass when output will be re-entered: add_cycle reads the prior run's registered/ and segmentation/. Without it, cyclic-IF becomes structurally impossible. ParamUtils.validateCleanup refuses the combination at launch.
