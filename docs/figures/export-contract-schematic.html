Supplementary Figure S6 · the export contract

What a phenotyped run hands to QuPath: three files, six numbers per cell, and why the container costs more than the content

S1 · pipeline S2 · registration S3 · quality control S4 · failure semantics S5 · phenotyping yield S6 · the export contract

The obvious reading is that cells.geojson is the contract. It is not. The downstream extension never parses GeoJSON — QuPath imports the file and the extension reads QuPath's per-detection measurement map. Every per-cell number therefore has to survive a round trip through QuPath's object model as a named double, and that single constraint decides the shape of everything below: what can be a measurement, what has to be a sidecar, and why the file is 3.5 GiB for a million cells when the same information is 0.56 GiB in a columnar layout.

a

The constraint nobody chose

The consumer reads QuPath detections, not files. So the transport is fixed before any design decision is taken — and it is the most expensive part of the contract.

what people assume

Mirage writes cells.geojson; the extension opens it. If that were true, the file format would be a free choice.

what actually happens

PathIO.readObjects parses the GeoJSON into QuPath objects (assets/import_geojson.groovy:142); the extension then reads each detection's measurement map. It never sees the file.

the consequence

Every per-cell datum must be a numeric measurement with a name. Anything that cannot be is forced into a sidecar — or dropped.

Why this is the whole story. A named double in JSON text costs roughly 25–45 bytes; the same value in a binary column costs 8. The contract below is close to optimal given that transport. The transport is where the remaining 6× sits.
b

c

Why two sidecars and not one

The split is forced by when each fact is computed, not by taste.

panel facts — run level

COMPILE_PANEL runs once per run. The tree, the palette, the constraint table and the marker roles are identical for every patient.

calibration facts — per patient

PHENOTYPE runs once per patient, and the dead band depends on that patient's cells, that patient's density bins and the α chosen for them.

A merged file would be wrong for every patient but one. Thresholds are the only thing in the contract that is genuinely per-patient; putting them in a run-level file is not a size trade-off, it is a correctness error.

e

A field earns its place per cell only if it is not derivable from something already present — or if a human filters on it in a UI that cannot compute.

Derivable is not the same as removable. Two derivable fields were deliberately kept for the viewer, and two were dropped because nobody filters on them. The distinction is the UI, not the information.
f

The trade that shrank the block: thresholds instead of p-values

Two numbers per marker per density bin replace two numbers per marker per cell. The sign is then reconstructed from the raw intensity that is already on the feature.

the rule
entry = thresholds[marker]
bin   = entry.collapsed ? 0 : cell["_pheno.density_bin"]
value = cell[entry.measurement]
pos   = value >  bins[bin].t_pos        neg = value <  bins[bin].t_neg
two fields exist only because the naive version is wrong

collapsed — calibration collapses per marker, while the cell carries the pre-collapse bin, so a collapsed marker must be read at bin 0.
measurement — the classifier falls back to the bare <marker> column when the compartment key is missing for that patient, so the column read is a per-patient fact.

two details that look cosmetic and are not

Comparisons are strict: a threshold is the last reference score that fails the conformal bound, so a value sitting exactly on it is not a confident call.
t_pos and t_neg may cross — the overlap is a real contradiction band and is reported, not clamped.

Not exact everywhere. The exporter rounds intensities to 4 decimals while the classifier read full precision, so the reconstruction is exact only outside one rounding unit (5×10−5) of a threshold.
g

Same information, cheaper containers

The load cost is dominated by the transport, not the payload. Three of these four options carry byte-identical information; they differ only in how QuPath gets to it.

The cheapest real win needs no code. Import the GeoJSON once with the provided script, then save the image into a QuPath project — every subsequent open reads the binary store instead of re-parsing 3.5 GiB of text. The columnar option is strictly better on size but is not reachable without changing how the consumer reads cells, because today it reads QuPath detections rather than files (panel a).
h

What this contract does not do

Stated so the figure is not read as a claim of completeness.

it does not compress the marker block

90% of the file is marker intensities and morphology, untouched by any of this. Every saving described here is inside the remaining 10%.

it does not resolve uncertainty

An ambiguous cell is exported as suspended, with the markers still undetermined named in free_mask. Nothing here decides it; a human does.

the columnar figure is arithmetic, not a benchmark

0.56 GiB is 8 bytes × the emitted value count. No columnar reader exists on either side, so no load time was measured for it.

the consumer is not on main

The extension that reads this contract lives on an unmerged branch, and the producer side does too. Both halves are parked.

Supplementary Figure S6 — the export contract. A phenotyped Mirage run publishes five artifacts, of which the downstream QuPath extension reads three, all in one directory: cells.geojson for geometry, classification and per-cell measurements, plus two JSON sidecars that are projections of artifacts produced earlier in the pipeline. The split between them follows the only seam that matters — panel facts are computed once per run, calibration facts once per patient, and the per-marker sign thresholds are the one thing that genuinely cannot be shared between patients. Per cell the contract is six dense measurements and one per surviving candidate, down from sixty-five, because everything reconstructible from the thresholds sidecar was moved off the cells. What remains is dominated not by phenotyping but by marker intensities, and above all by the container: the consumer reads QuPath detections rather than files, so every value travels as named JSON text at roughly five times its binary size. The practical consequence is smaller than it sounds — importing once and saving a QuPath project replaces the parse with a binary load — and the larger one is architectural: a columnar side table keyed by cell label would carry the same information in 0.56 GiB instead of 3.54, but only if the consumer were changed to read a file rather than a detection.
