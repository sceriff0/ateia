# Usage

## Samplesheet (Input CSV)

MIRAGE uses a CSV manifest as `--input`. The required columns differ by `--start`.

### Step: `preprocessing`

Provide one row per image file. Exactly one row per patient must have `is_reference` set to `true`; this image defines the registration target coordinate space.

Required columns:

| Column | Description |
|---|---|
| `patient_id` | Unique patient/sample identifier |
| `path_to_file` | Absolute path to the raw image (any Bio-Formats-compatible format) |
| `is_reference` | `true` for the reference panel, `false` for all others |
| `channels` | Pipe-separated channel names in acquisition order (e.g. `DAPI|CD3|CD8`) |

Example:

```csv
patient_id,path_to_file,is_reference,channels
P001,/data/P001_panel1.nd2,true,DAPI|CD3|CD8|CD4
P001,/data/P001_panel2.nd2,false,DAPI|PANCK|SMA|VIMENTIN
P002,/data/P002_panel1.nd2,true,DAPI|CD3|CD8|CD4
P002,/data/P002_panel2.nd2,false,DAPI|PANCK|SMA|VIMENTIN
```

### Step: `registration`

Use the `results/{patient_id}/csv/preprocessed.csv` generated by the preprocessing step, or construct an equivalent file manually.

Required columns:

| Column | Description |
|---|---|
| `patient_id` | Unique patient/sample identifier |
| `preprocessed_image` | Absolute path to the illumination-corrected OME-TIFF |
| `is_reference` | `true` for the reference panel image |
| `channels` | Pipe-separated channel names |

Example:

```csv
patient_id,preprocessed_image,is_reference,channels
P001,/results/P001/preprocessed/P001_corrected.ome.tif,true,DAPI|CD3|CD8|CD4
P001,/results/P001/preprocessed/P001_panel2_corrected.ome.tif,false,DAPI|PANCK|SMA|VIMENTIN
```

### Step: `postprocessing`

Use the `results/{patient_id}/csv/registered.csv` generated by the registration step, or construct an equivalent file manually.

Required columns:

| Column | Description |
|---|---|
| `patient_id` | Unique patient/sample identifier |
| `registered_image` | Absolute path to the registered OME-TIFF |
| `is_reference` | `true` for the reference panel image |
| `channels` | Pipe-separated channel names |

Example:

```csv
patient_id,registered_image,is_reference,channels
P001,/results/P001/registered/P001_registered.ome.tiff,true,DAPI|CD3|CD8|CD4
P001,/results/P001/registered/P001_panel2_registered.ome.tiff,false,DAPI|PANCK|SMA|VIMENTIN
```

### Validation Rules

- Exactly one `is_reference = true` row per `patient_id` at the `preprocessing` step.
- All image paths must exist on the filesystem at pipeline launch.
- The `channels` field must include `DAPI` and must match the image acquisition order.
- For checkpoint steps (`registration`, `postprocessing`), only the columns required for that step need to be present.

## Parameter Reference

Defaults are defined in `nextflow.config` (`params { ... }`). Full schema is in `nextflow_schema.json`. Parameter templates are provided in `params/`:

| Template | Purpose |
|---|---|
| `params/full_pipeline.json` | All steps from preprocessing |
| `params/preprocessing_only.json` | Preprocessing only |
| `params/registration_only.json` | Registration from checkpoint |
| `params/postprocessing_only.json` | Postprocessing from checkpoint |
| `params/test.json` | Minimal test run |

Pass a template with `-params-file params/full_pipeline.json` and override individual values on the command line.

### Input / Output

| Parameter | Default | Description |
|---|---|---|
| `input` | `''` | Path to samplesheet CSV (required for preprocessing, registration, postprocessing) |
| `outdir` | _(required)_ | Output root directory. No default — must be passed via `--outdir` or set by a profile. |
| `savedir` | `null` | Optional archive destination |
| `start` | `preprocessing` | Pipeline entry point: `preprocessing`, `registration`, `postprocessing` |
| `stop` | `null` | Pipeline step to stop after. When null, runs to end. Values: `preprocessing`, `registration`, `postprocessing` |
| `dry_run` | `false` | Validate inputs only, do not execute tasks |
| `debug_channels` | `false` | Enable `.view` debug output on channels |

### Preprocessing

| Parameter | Default | Description |
|---|---|---|
| `preproc_tile_size` | `1950` | Tile size for BaSiC illumination correction |
| `preproc_skip_dapi` | `true` | Skip illumination correction on the DAPI channel |
| `preproc_autotune` | `false` | Enable BaSiC autotune mode |
| `preproc_n_iter` | `100` | BaSiC optimization iterations |
| `preproc_pool_workers` | `3` | Parallel worker threads for tiled processing |
| `preproc_overlap` | `0` | Tile overlap in pixels |
| `preproc_no_darkfield` | `false` | Disable darkfield estimation |
| `preprocess_qc_scale_factor` | `0.25` | Downsample factor for preprocessing QC thumbnails |
| `pixel_size` | `0.325` | Physical pixel size in microns (used in pyramid metadata) |

### Registration — Common

| Parameter | Default | Description |
|---|---|---|
| `allow_auto_reference` | `false` | Allow pipeline to select reference image automatically |
| `padding` | `false` | Pad images to a common canvas after registration |
| `pad_mode` | `constant` | Padding fill mode (`constant`, `reflect`, etc.) |
| `skip_registration_qc` | `false` | Skip generation of registration QC overlays |
| `qc_scale_factor` | `0.25` | Downsample factor for registration QC thumbnails |
| `enable_feature_error` | `false` | Compute feature-based registration error metrics |
| `feature_detector` | `superpoint` | Feature detector for error estimation |
| `feature_max_dim` | `1024` | Max image dimension for feature detection |
| `feature_n_features` | `5000` | Number of features to detect |

### Registration — VALIS

| Parameter | Default | Description |
|---|---|---|
| `reg_reference_markers` | `["DAPI","FITC"]` | Channel names used as reference markers |
| `memory_mode` | `medium` | VALIS memory mode (`low`, `medium`, or `high`) |
| `reg_micro_reg_fraction` | `0.125` | Fraction of image used for micro-registration |
| `reg_max_image_dim` | `4000` | Max image dimension during VALIS registration |
| `skip_micro_registration` | `true` | Skip VALIS micro-registration step |
| `reg_parallel_warping` | `false` | Enable parallel warping in VALIS |
| `reg_n_workers` | `8` | Number of VALIS worker threads |
| `reg_use_tiled_registration` | `true` | Use tiled registration in VALIS |
| `reg_tile_size` | `2048` | Tile size for VALIS tiled registration |

### Segmentation

| Parameter | Default | Description |
|---|---|---|
| `seg_gpu` | `true` | Use GPU for StarDist inference |
| `seg_pmin` | `1.0` | Lower percentile for image normalization |
| `seg_pmax` | `99.8` | Upper percentile for image normalization |
| `seg_n_tiles_y` | `16` | Number of inference tiles along Y axis |
| `seg_n_tiles_x` | `16` | Number of inference tiles along X axis |
| `seg_expand_distance` | `10` | Pixels to expand detected nuclei to cell boundary |
| `segmentation_model_dir` | `null` | Path to custom StarDist model directory (uses bundled model if null) |
| `segmentation_model` | *(bundled)* | Name of the StarDist model to use |

### Quantification

| Parameter | Default | Description |
|---|---|---|
| `quant_min_area` | `10` | Minimum cell area in pixels to retain for quantification |

### Pixie Clustering (Planned)

Pixel- and cell-level clustering via Pixie is **not currently wired** into the pipeline. The `containers/pixie/` Dockerfile exists for future integration — see the upstream [angelolab/pixie](https://github.com/angelolab/pixie) project for the algorithm itself. No `pixie_*` parameters are accepted today; the table below will be filled in when the integration lands.

### Pyramid Export

| Parameter | Default | Description |
|---|---|---|
| `tilex` | `512` | Tile width in pixels for pyramidal OME-TIFF |
| `tiley` | `512` | Tile height in pixels |
| `pyramid_resolutions` | `8` | Number of pyramid resolution levels |
| `pyramid_scale` | `2` | Downsampling factor between pyramid levels |
| `compression` | `zstd` | Compression codec (`zstd`, `lzw`, `jpeg`, etc.) |

### Infrastructure and Limits

| Parameter | Default | Description |
|---|---|---|
| `max_memory` | `700.GB` | Maximum memory cap for any process |
| `max_cpus` | `128` | Maximum CPU cap for any process |
| `max_time` | `240.h` | Maximum walltime cap for any process |
| `slurm_partition` | `null` | SLURM partition name |
| `slurm_account` | `null` | SLURM account name |
| `slurm_qos` | `null` | SLURM QOS name |
| `gpu_type` | `null` | GPU type hint (e.g. `nvidia_h200:1`) for SLURM GRES |
| `publish_dir_mode` | `copy` | How outputs are published (`copy`, `symlink`, `move`) |
| `enable_trace` | `true` | Generate Nextflow trace, report, and timeline files |
| `trace_dir` | `.trace` | Directory for trace output files |

## Example Commands

### Full pipeline

```bash
nextflow run main.nf \
  --input samplesheet.csv \
  --outdir results \
  --start preprocessing \
  -profile slurm \
  -params-file params/full_pipeline.json
```

### Registration-only from preprocessed checkpoint

```bash
nextflow run main.nf \
  --input results/P001/csv/preprocessed.csv \
  --start registration \
  --outdir results \
  -profile slurm \
  -resume
```

### Postprocessing-only from registered checkpoint

```bash
nextflow run main.nf \
  --input results/P001/csv/registered.csv \
  --start postprocessing \
  --outdir results \
  -profile slurm \
  -resume
```

### Dry-run validation

```bash
nextflow run main.nf \
  --input samplesheet.csv \
  --start preprocessing \
  --dry_run true
```

## Execution Profiles

Profiles are defined in `nextflow.config`:

| Profile | Description |
|---|---|
| `slurm` | SLURM cluster submission (default for HPC) |
| `local` | Local execution without a scheduler |
| `docker` | Local execution using Docker containers |
| `singularity` | Container execution using Singularity/Apptainer |
| `test` | Minimal test dataset and reduced resource limits |

Combine profiles as needed:

```bash
-profile slurm,singularity
```

## Site-Specific Configuration

For institution-specific SLURM settings, create a custom config file and load it via `-c`:

```bash
nextflow run main.nf \
  -c /path/to/my_site.config \
  -profile slurm \
  --input samplesheet.csv \
  --outdir results \
  --start preprocessing
```

A minimal site config might look like:

```groovy
params {
    slurm_partition = 'compute'
    slurm_account   = 'myproject'
    max_memory      = '500.GB'
    max_cpus        = 64
    max_time        = '120.h'
}
```

---

## Resuming a Failed Run

Nextflow caches completed tasks in the `work/` directory. Add `-resume` to any command to skip already-completed tasks:

```bash
nextflow run main.nf -resume \
  --input samplesheet.csv \
  --start preprocessing \
  --outdir results \
  -profile slurm
```
